# GitHub 项目发布层补齐设计

日期：2026-09-01

## 背景

美学身份卡网页的核心功能已经完成，并推送到 GitHub 分支 `codex/aesthetic-identity-card-ui`。当前仓库能够展示源代码，但缺少面向首次访问者的项目说明、隐私文档、许可证、界面预览和可直接访问的在线体验页。

本次工作只补齐 GitHub 项目的发布层，不修改面部分析、问卷、身份卡、挑战、照片对比、日历或分享逻辑。

## 目标

1. 访问 GitHub 分支时，用户能在一分钟内理解项目用途、主要能力、隐私边界和运行方式。
2. 提供一个无需下载代码即可打开的 GitHub Pages 在线体验地址。
3. 用不包含私人照片的手机端截图展示视觉方向。
4. 明确代码采用 MIT 许可证。
5. 保持现有单文件网页结构，不增加构建工具或重复网页副本。

## 非目标

- 不覆盖远程旧 `main`。
- 不迁移到微信小程序。
- 不把 Face-API.js、Tailwind、html2canvas 或模型权重下载进仓库。
- 不承诺离线运行。
- 不新增后端、账号、数据库或云端照片存储。
- 不修改现有产品功能或判断规则。

## 方案选择

采用 GitHub Actions 官方 Pages 流程，从分支 `codex/aesthetic-identity-card-ui` 部署仓库中的静态网页。

该方案优于把网页复制到 `docs/`：它保持 `index.html` 为唯一产品源码，避免两份页面内容产生差异。该方案也优于接入 Vercel：不增加外部平台和账号依赖。

## 交付文件

### `README.md`

README 使用中文，包含：

- 产品定位和一句话价值说明。
- 在线体验入口和源码分支入口。
- 手机端界面预览图。
- 核心功能：照片质量检查、参考级继续分析、六维差异图谱、可读数据、身份卡保存分享、挑战与打卡。
- 隐私原则：照片在浏览器本地处理，身份卡不是美貌、医疗或健康评价。
- 本地运行方式：推荐通过本地静态服务器访问，不直接依赖 `file://`。
- 技术栈和 CDN 依赖说明。
- 当前限制：需要网络加载依赖和模型；结果受照片角度、光线、镜头和算法启发式影响。
- 测试命令和许可证链接。

### `PRIVACY.md`

隐私文档包含：

- 面部照片用于浏览器内分析，不由本项目服务器接收。
- 身份卡照片和本次分析状态的生命周期。
- 挑战状态、打卡记录和可选前后对比照片使用浏览器本地存储。
- 教程链接和提醒设置的本地保存范围。
- 用户如何通过浏览器站点数据设置清除本地数据。
- GitHub Pages 和第三方 CDN 可能产生常规网络请求，但不上传用户选择的照片。
- 非医疗建议、非诊断、非美貌评价声明。

### `LICENSE`

使用标准 MIT License，版权年份为 2026，版权所有者使用 GitHub 仓库账号 `najeebjb724-star`。

### `assets/preview.png`

### `.github/workflows/deploy-pages.yml`

工作流要求：

- 在 `codex/aesthetic-identity-card-ui` 分支推送时运行。
- 支持 `workflow_dispatch` 手动运行。
- 使用 GitHub 官方 Pages Actions。
- 权限限制为 `contents: read`、`pages: write`、`id-token: write`。
- 使用并发组避免多个部署互相覆盖。
- 上传当前仓库静态内容并部署到 `github-pages` 环境。
- 不执行任意第三方部署脚本。

## 数据与安全边界

- 新增文档不包含用户照片、测试照片、浏览器本地数据或密钥。
- 工作流不使用自定义 secrets。
- 部署只读取仓库内容并写入 GitHub Pages。
- README 不声称算法能判断美丑、健康、疾病或适合所有人群。
- README 和隐私文档明确 CDN 与模型加载需要网络。

## 验证

实施完成后验证：

1. `node --test tests/*.test.cjs` 全部通过。
2. 两段内联脚本能够被 Node `vm.Script` 解析。
3. YAML 能被解析，且分支、权限、Pages 官方 Actions 配置正确。
4. README 中的相对链接和截图路径存在。
5. 首页截图尺寸为 390 × 844，且不含私人照片。
6. 本地静态服务器打开 `index.html` 时没有新增运行错误。
7. Git diff 只包含本次发布层文件，不修改产品功能代码；如果截图需要临时启动页面，不提交任何临时测试素材。

## 发布流程

1. 在本地 `main` 上增加发布层文件并运行验证。
2. 提交发布层改动。
3. 将当前提交推送到远程分支 `codex/aesthetic-identity-card-ui`，不覆盖远程 `main`。
4. 检查 GitHub Actions 运行结果。
5. 如果 Pages 需要首次授权，提示用户在仓库设置中启用 GitHub Actions 作为 Pages Source。
6. 部署成功后提供源码分支、Actions 和在线体验三个链接。
