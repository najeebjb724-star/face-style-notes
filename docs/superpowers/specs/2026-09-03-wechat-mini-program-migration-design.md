# 美学身份卡微信小程序完整版迁移设计

## 一、背景与目标

当前产品是单文件网页 MVP，已经验证以下核心链路：

- 上传正面照片并进行质量检查。
- 基于 68 点关键点计算脸型、三庭五眼和其他比例。
- 生成可读的美学身份卡、建议和分享图片。
- 创建习惯养成或变美训练挑战，完成打卡、照片对比和结营海报。

下一阶段将产品重构为可正式提审的微信原生小程序。目标用户仍是 18–25 岁年轻女性，产品情绪保持“专属感、仪式感、被读懂”，而不是冷冰冰的人脸评分。

本次采用完整版范围：照片分析、身份卡、挑战打卡、前后照片、手机日历、微信提醒、海报分享、跨设备同步和数据管理同时纳入正式小程序。

## 二、已确认的关键决定

1. 采用微信原生小程序，不使用 `web-view` 套壳。
2. 主体暂按个人主体准备，服务内容定位为非医疗美容与生活工具。
3. 后端统一采用微信云开发 CloudBase。
4. 人脸模型运行在微信云托管的独立容器服务中，与业务数据库隔离。
5. 用户单独同意后，照片加密上传云端；分析结束立即删除原图。
6. 长期保存比例结果和身份卡，不长期保存分析原图。
7. 习惯养成和变美训练营共用同一个挑战系统。
8. 第一版不加入支付、排行榜、社区、陌生人互动和会员体系。
9. 计划用四周完成首次可提审版本，并额外预留备案和平台审核时间。

## 三、产品信息架构

小程序采用三个底部入口：

### 3.1 首页

- 新用户看到“开始面部解读”和“先做一个变美挑战”。
- 老用户同时看到进行中的挑战和最近一张美学身份卡。
- 首页不要求填写注册资料，微信基础登录在需要云端同步时自然完成。

### 3.2 挑战

- 模板选择与可选自定义。
- 今日唯一主任务。
- 打卡日历、补记昨天和撤销当天打卡。
- 开始照、结束照和可选阶段照。
- 日历与订阅提醒设置。
- 结束复盘、完成海报和分享入口。

### 3.3 我的

- 历史身份卡。
- 当前与历史挑战。
- 照片和数据保存设置。
- 删除单份记录、清空全部数据、撤回同意和账户数据注销。
- 隐私保护指引与算法说明。

分析报告不是独立底部入口。每次分析完成后进入沉浸式长页面，并从建议卡直接创建对应挑战，避免分析和行动彼此割裂。

## 四、首次分析链路

```text
首页开始面部解读
  → 说明处理目的、保存内容和删除规则
  → 用户单独同意处理本次人脸照片
  → 拍照或从相册选择
  → 本地压缩和照片质量预检
  → 加密上传临时存储
  → 云托管模型提取关键点
  → 比例算法生成结构化结果
  → 保存报告并删除分析原图
  → 展示美学身份卡和可读结论
  → 保存、分享或创建推荐挑战
```

用户不同意人脸照片处理时，仍可进入挑战模块。质量检查发现倾斜、遮挡、过暗或脸部过小时，应说明会影响哪些结果，并始终同时提供“重新拍一张”和“仍用这张照片分析”。低质量照片生成的报告明确标注为参考结果。

报告先展示能被记住的结论，再展示数据：

- 脸型与风格定位。
- 一句话整体描述。
- 三庭五眼的自然语言解释。
- 值得保留的优势特征。
- 可观察、可撤销、非医疗的改善建议。
- 支撑结论的比例和置信度。

## 五、挑战闭环

```text
选择模板或从报告接受推荐
  → 确认天数、频率和提醒时间
  → 可选添加教程链接
  → 加入手机日历或订阅微信提醒
  → 每天完成一个明确任务
  → 在关键节点留下可选照片
  → 挑战结束后查看复盘
  → 生成带小程序码的分享海报
```

### 5.1 模板

第一版保留两类模板，但使用相同的数据结构和页面：

- 习惯养成：身体乳、防晒、清洁工具等。
- 变美训练：完整妆容、眼妆、眉妆等。

系统根据报告把最相关模板放在首位，但不自动创建。没有报告的用户也可以直接选模板。自定义入口只要求名称、持续天数、频率和提醒时间。

### 5.2 每日任务

- 首屏只突出一个主操作：“完成今日打卡”。
- 当天可撤销；允许补记昨天，不设计积分惩罚。
- 教程链接放在任务内部，需要时才离开小程序。
- 外部教程返回后保留当前任务状态。
- 拒绝提醒不会阻止挑战继续使用。

### 5.3 照片与分享

- 开始照、结束照和阶段照均为可选项。
- 没有照片也能完成挑战并生成文字复盘。
- 默认分享海报不展示具体脸部比例或缺点标签。
- 海报可包含用户主动选择的对照照、完成度、成果描述和小程序码。

## 六、系统架构

### 6.1 小程序客户端

使用 WXML、WXSS 和 JavaScript 实现：

- 页面和组件渲染。
- 拍照、相册选择与上传前压缩。
- 本地照片质量预检。
- 身份卡与挑战海报 Canvas 渲染。
- 手机日历、订阅授权、相册保存和好友分享。
- 离线打卡队列与网络恢复后的同步。

### 6.2 微信云开发

负责：

- 微信用户身份映射。
- 报告、挑战、打卡、授权和删除状态。
- 临时分析照片与可选挑战照片存储。
- 云函数业务校验。
- 订阅消息定时发送。
- 删除任务、失败重试、审计日志和告警。

小程序客户端不直接持有云端管理密钥，也不能直接修改其他用户的数据。涉及创建分析任务、保存报告、发送消息和删除照片的操作必须经过云函数。

### 6.3 人脸分析服务

模型作为独立容器部署在微信云托管中。服务只接受短期任务凭证，只能读取与当前任务关联的临时照片，无权查询用户档案或挑战记录。

分析服务保持与现有算法兼容的输出契约：

- 单张主脸检测结果。
- 68 个标准化关键点。
- 检测和关键点置信度。
- 照片质量指标。
- 模型与规则版本号。

比例、脸型和风格规则作为独立纯函数模块迁移，输入为标准化关键点和问卷信息，输出为结构化报告。这允许未来替换模型而不重写产品页面。

## 七、数据结构

首版使用以下集合：

- `users`：用户标识、创建时间、隐私版本和状态。
- `consents`：同意类型、文本版本、时间、撤回时间和任务编号。
- `analysis_jobs`：任务状态、质量状态、错误码、创建和删除时间。
- `reports`：标准化比例、脸型、风格、可读结论、模型版本和规则版本。
- `challenges`：模板、天数、频率、提醒、状态和所有者。
- `checkins`：挑战、日期、完成状态和同步时间。
- `challenge_photos`：挑战、节点、存储标识、保存策略和删除时间。
- `message_subscriptions`：模板、授权结果、可发送状态和使用时间。
- `deletion_jobs`：对象类型、对象标识、重试次数、最后错误和最终状态。

每条私有业务数据都绑定用户标识。报告和挑战通过独立 ID 关联，不把完整关键点坐标复制到客户端或技术日志中。

## 八、数据保存和隐私规则

### 8.1 分析原图

- 仅在本次分析单独同意后上传。
- 正常情况下在分析结束后立即删除。
- 分析失败、退出或网络异常时仍进入删除队列。
- 异常情况下最长保留 30 分钟。
- 删除暂时失败时持续重试并告警，不提前向用户宣称已删除。

### 8.2 挑战照片

- 与分析原图分开存储和授权。
- 默认在挑战结束后保留 7 天，方便生成和重新下载海报。
- 用户可以立即删除，或主动选择长期收藏。
- 删除挑战时同时删除关联照片和待发送提醒。

### 8.3 长期数据

- 比例结果、身份卡、挑战和打卡默认跨设备保存。
- 用户可以删除单份报告、单个挑战或全部账户数据。
- 技术日志只记录任务编号、状态、耗时和错误码，不记录照片或完整人脸数据。

## 九、提醒、日历与分享

- 日常重复提醒优先使用手机系统日历，由系统弹窗让用户确认添加。
- 微信订阅消息只在用户主动点击后申请授权。
- 产品不能承诺普通美容类个人小程序获得永久、无限次微信提醒。
- 用户拒绝订阅消息后，挑战页和手机日历仍能完成闭环。
- 好友分享使用小程序页面分享能力。
- 完成海报使用 Canvas 生成临时图片，再由用户授权保存相册。
- 小程序码由服务端生成，访问令牌不得出现在客户端代码中。

## 十、失败恢复

- 上传失败：保留照片选择和当前页面，允许继续重试。
- 分析超时：显示可理解的失败信息，允许重新分析；原任务进入删除队列。
- 低置信度：说明受影响的数据，允许重拍或继续获得参考报告。
- 删除失败：后台重试、告警和记录人工处置状态。
- 离线打卡：本地排队，恢复网络后幂等同步，避免重复记录。
- 云端冲突：按挑战与日期唯一键合并，不以客户端整份覆盖服务端记录。
- 提醒拒绝：不重复骚扰授权，保留日历和小程序内任务入口。
- 海报失败：保留报告或挑战完成状态，允许单独重新生成。

## 十一、测试策略

### 11.1 自动化测试

- 迁移现有比例、脸型和挑战规则单元测试。
- 为云函数编写权限、幂等、同步冲突和删除队列测试。
- 为分析服务编写输入格式、无脸、多脸、低置信度和超时测试。
- 使用固定关键点样本验证网页与小程序报告结果一致。

### 11.2 隐私与安全测试

- 验证未同意时无法创建分析任务。
- 验证用户不能读取或修改其他用户的报告、挑战和照片。
- 验证成功、失败、退出和超时四条路径都会删除分析原图。
- 验证日志、错误信息和监控中不出现照片内容和敏感密钥。
- 验证撤回同意、单份删除和全部清空均可完成。

### 11.3 真机测试

- 至少覆盖一台较新 iPhone、一台较旧 iPhone、一台主流安卓和一台低性能安卓。
- 覆盖 Wi-Fi、移动网络、弱网、断网恢复和小程序被系统回收。
- 覆盖拍照、相册、日历、订阅、保存相册和好友分享的授权拒绝与重新开启。
- 验证小屏、安全区、系统字体放大和长报告滚动。

## 十二、四周开发节奏

### 第 1 周：基础框架与挑战

- 第 1 天：注册个人主体小程序、获取 AppID、创建云开发环境。
- 第 2–3 天：原生页面、三入口、微信登录和数据库权限。
- 第 4–7 天：挑战模板、创建、打卡、进度同步和基本照片记录。

### 第 2 周：照片与分析

- 单独同意、拍照、相册、压缩和质量检查。
- 云托管部署 68 点关键点模型。
- 比例与风格规则迁移。
- 原图删除、失败恢复和删除队列。

模型容器是本周主要风险。如果第 2 天仍无法稳定输出约定的 68 点结果，应立即缩小问题到“固定图片输入—结构化关键点输出”的最小服务，暂停报告页面联调，先解决模型服务。

### 第 3 周：报告、身份卡和分享

- 完整可读报告和推荐挑战。
- 身份卡、对照页、完成复盘和海报。
- 小程序码、保存相册和好友分享。
- 统一完成一次视觉精修，不在前两周逐页反复打磨动画。

### 第 4 周：提醒、隐私与提审

- 手机日历和订阅消息。
- 数据管理、撤回同意和注销。
- 隐私保护指引、算法说明和审核材料。
- 真机、弱网、权限拒绝和回归测试。
- 修复阻断问题并提交审核。

备案和平台审核耗时不计入四周开发周期，应并行准备并预留额外时间。

## 十三、上线验收标准

- 用户能在 3 分钟内完成首次分析并看到身份卡。
- 不同意照片处理的用户仍能使用挑战功能。
- 照片不合格时可以重拍，也可以坚持分析。
- 分析原图正常立即删除，异常不超过 30 分钟。
- 打卡、挑战和报告可跨设备恢复。
- 没有授权提醒、相册或挑战照片，也能使用其余核心功能。
- 海报默认不公开具体脸部比例或负面标签。
- 所有结论使用“比例参考、风格倾向和观察建议”，不提供医疗诊断或效果保证。
- 用户可以删除单份报告、挑战照片、整个挑战或全部账户数据。
- 自动化测试、隐私路径测试和规定真机矩阵全部通过后才提交审核。

## 十四、上线准备清单

- 注册个人主体微信小程序并取得 AppID。
- 选择与实际功能匹配的个人主体服务类目，以提交时公众平台可选范围为准。
- 创建开发和生产两个隔离的云开发环境。
- 完成小程序备案并在规定位置展示备案信息。
- 配置用户隐私保护指引和隐私授权弹窗。
- 准备人脸照片单独同意文本、挑战照片保存说明和删除说明。
- 配置订阅消息模板、相册和日历相关权限说明。
- 准备审核人员可完成全链路的测试数据与操作说明。
- 在 README 中说明环境配置、云函数、模型容器、数据库集合、发布和回滚步骤。

## 十五、主要风险与控制

- **个人主体类目变化**：注册后立即以后台实际可选类目核验；避免医疗美容、诊断和疗效承诺。
- **模型容器不稳定**：优先完成最小模型服务和固定样本基准，再接页面和规则。
- **四周节奏过紧**：功能完整优先，第三周集中视觉精修；每日保留可运行版本。
- **删除流程失效**：所有任务以删除状态收尾，独立重试队列和告警，不依赖单次函数成功。
- **订阅提醒受限**：手机日历和小程序内今日任务始终可用，不把微信推送作为唯一回流方式。
- **照片分享泄露隐私**：默认海报不带详细脸部数据，对照照必须由用户主动选择。
