# 科学变美基础版设计规格

**日期：** 2026-08-26  
**产品：** 看脸找风格  
**交付形式：** 单文件 `index.html`，移动端优先，本地浏览器运行

## 1. 目标

把现有“上传照片后给出脸型与风格建议”的 MVP，升级为适合初学者的科学变美基础工具。新版通过照片几何测量与六问自评，给出可解释、有可信度标记、可执行的妆容、发型、穿搭和基础护肤建议。

报告回答三个问题：

1. 照片实际测到了什么？
2. 这些数据可能带来什么视觉感受？
3. 用户接下来可以低成本尝试什么？

## 2. 非目标与安全边界

- 不生成美貌分、颜值排名或“完美比例”。
- 不根据脸部推断健康、疾病、年龄、性格、族群或社会属性。
- 不把古典三庭五眼或黄金比例描述为普适审美标准。
- 不从照片判断肤质、敏感史或皮肤疾病；肤质倾向来自用户自评。
- 不提供医美项目、处方药、治疗方案或诊断性建议。
- 不保存、上传或远程处理照片、关键点和问卷结果。
- 不引入账号、服务器或数据库。

## 3. 依据体系

每一条报告结论必须标记为以下三类之一：

1. **几何测量：** 由 Face-API.js 68 点关键点与像素数据直接计算。结果受角度、光线、表情和模型误差影响。
2. **造型经验：** 根据视觉重心与线条平衡生成的妆发穿搭建议，不作为医学或审美事实。
3. **通用护理：** 来自皮肤科机构公开的低风险护肤基础原则。

三庭五眼只作为古典视觉参照。跨族群面部测量研究显示面部比例存在明显人群差异，因此产品只说“相对参考关系”，不说“达标”或“不达标”。

## 4. 技术架构

继续使用一个 `index.html`，但 JavaScript 内部按职责分为六个模块：

1. `modelLoader`：加载 Face-API.js、Tiny Face Detector 与 68 点模型。
2. `qualityGate`：检查文件、单人脸、拍摄角度、清晰度、亮度和脸部占比。
3. `measurementEngine`：只计算原始比例、角度和左右差异。
4. `questionnaireEngine`：收集六问并推导肤质与使用约束。
5. `knowledgeBase`：保存公式说明、参考类型、可信度因素、造型规则和资料来源。
6. `reportComposer`：把测量、问卷和知识表组合成报告与 30 天行动卡。

所有状态保存在内存中的 `appState`。刷新或关闭页面后自动清除。

## 5. 用户流程

### 5.1 模型加载

- 页面打开后显示两个模型的真实加载进度。
- 模型失败时显示失败阶段、重试按钮和网络提示。
- 模型未就绪时禁用照片选择。

### 5.2 拍照指导

上传区在选图前展示以下要求：

- 正面看镜头，保持自然表情，嘴唇轻闭。
- 头发不要遮挡眉毛、脸颊和下颌；摘下眼镜和夸张饰品。
- 使用均匀自然光，避免逆光、强滤镜和美颜。
- 手机与脸保持约一臂距离，避免近距离广角自拍。
- 画面包含完整头顶、双耳附近轮廓和下巴。

### 5.3 照片质量门槛

质量门槛先于任何风格结论。产品阈值用于控制测量误差，不代表医学标准。

| 检查 | 计算 | 处理 |
|---|---|---|
| 图片格式 | MIME 为 `image/*`，文件不超过 20MB | 不合格时拒绝读取 |
| 人脸数量 | `detectAllFaces()` 结果 | 0 张或多于 1 张时拒绝 |
| 检测置信度 | Tiny Face Detector score | `<0.55` 时要求更清晰照片 |
| 脸部大小 | 检测框宽度 / 图片宽度 | `<0.28` 提示靠近；`>0.85` 提示稍远 |
| 最小细节 | 压缩后检测框宽度 | `<180px` 时要求更高分辨率照片 |
| 眼睛水平 | 两眼中心连线角度 | `≤3°` 高可信；`3–5°` 可用；`>5°` 拒绝 |
| 左右偏转代理 | 鼻尖到左右脸边距离差 / 脸宽 | `≤0.08` 高可信；`0.08–0.12` 中；`>0.12` 拒绝 |
| 模糊度 | 256×256 灰度脸区 Laplacian variance | `<45` 提示照片可能模糊 |
| 亮度 | 灰度脸区平均值（0–255） | `<55` 过暗；`>215` 过曝 |

通过后显示总可信度“高”或“中”。任一角度项目为“中”时，对称数据默认折叠并显示角度警告。

### 5.4 六问自评

问卷在照片质量通过后出现，每题单选：

1. **洁面 30 分钟后：** 明显紧绷或起皮 / 基本舒适 / T 区发亮 / 全脸较快发亮。
2. **产品耐受：** 经常刺痛发红 / 偶尔 / 很少。
3. **当前第一目标：** 肤质基础 / 日常妆容 / 发型修饰 / 整体风格。
4. **每日可投入时间：** 5 分钟 / 15 分钟 / 30 分钟。
5. **头发维护：** 不染烫且尽量免打理 / 可吹整或轻度染烫 / 可接受定期染烫和造型。
6. **每月预算：** 基础 / 适中 / 进阶。

肤质倾向只依据第 1 题：干性倾向、正常倾向、混合倾向或油性倾向。第 2 题单独生成“敏感倾向”，不与肤质合并。未答完问卷时仍可查看照片测量，但不生成护肤路线和 30 天完整计划。

## 6. 面部测量

所有线性数据都归一化为比例，避免受到图片缩放影响。角度使用 `atan2` 计算为度数。

### 6.1 整体轮廓

| 数据 | 公式 | 说明 |
|---|---|---|
| 脸宽 | `abs(p16.x - p0.x)` | 归一化基准 |
| 可见纵向长度 | `abs(p8.y - p27.y)` | 鼻根至下巴，不包含真实发际线 |
| 估算总脸长 | `可见纵向长度 × 1.8` | 兼容现有脸型逻辑，必须标“估算” |
| 脸长宽比 | `估算总脸长 / 脸宽` | 脸型产品启发式依据之一 |
| 颧部宽比 | `distance(p2,p14) / 脸宽` | 描述中上脸横向存在感 |
| 下颌宽比 | `distance(p4,p12) / 脸宽` | 描述下脸横向线条 |
| 下巴宽比 | `distance(p6,p10) / 脸宽` | 描述下巴收窄程度 |

脸型分类继续使用产品启发式，不宣称为人体测量诊断。报告必须展开显示触发分类的两个主要数据。

### 6.2 纵向比例

- 发际线估算：`p27.y - (p33.y - p27.y) × 1.2`，低可信度。
- 上庭：发际线估算至 `p27`。
- 中庭：`p27` 至 `p33`。
- 下庭：`p33` 至 `p8`。
- 三段除以总和后显示百分比。
- `<30%` 显示“相对短”，`30–36%` 显示“接近三等分参照”，`>36%` 显示“相对长”。这三个区间是产品解释带，不是人群常模。

### 6.3 眼部与五眼关系

| 数据 | 公式 | 产品解释 |
|---|---|---|
| 平均眼宽 | `(distance(p36,p39)+distance(p42,p45))/2` | 横向尺度 |
| 眼间距关系 | `distance(p39,p42)/平均眼宽` | `<0.85` 相对集中；`0.85–1.15` 接近一眼宽参照；`>1.15` 相对舒展 |
| 左右眼长宽比 | 眼宽 / 上下眼睑平均距离 | 描述眼裂形态，表情会影响 |
| 左右眼角倾斜 | 外眼角相对内眼角的角度 | `>3°` 上扬；`-3°–3°` 近水平；`<-3°` 下倾，均为造型描述 |
| 左右眼尺寸差 | `abs(左眼宽-右眼宽)/平均眼宽` | 只显示数据，不评价美丑 |

### 6.4 眉部

- 眉毛倾斜：左右眉首尾连线相对水平线的角度。
- 眉眼距离：眉毛平均 y 与对应眼睛中心 y 的距离 / 平均眼宽。
- 左右眉高度差：两侧眉毛中心 y 差 / 脸宽。
- 眉部建议只影响眉峰、眉头深浅和线条方向，不建议永久性改变。

### 6.5 鼻部与唇部

| 数据 | 公式 |
|---|---|
| 鼻宽/脸宽 | `distance(p31,p35) / 脸宽` |
| 鼻宽/眼间距 | `distance(p31,p35) / distance(p39,p42)` |
| 嘴宽/脸宽 | `distance(p48,p54) / 脸宽` |
| 上唇厚度代理 | `distance(p51,p62) / 脸宽` |
| 下唇厚度代理 | `distance(p66,p57) / 脸宽` |
| 上下唇关系 | `上唇厚度代理 / 下唇厚度代理` |
| 嘴角倾斜 | 左右嘴角连线角度 |

鼻部只给修容范围建议；唇部只给唇线、色彩面积和视觉重心建议。

### 6.6 下颌与左右差异

- 下颌曲线使用现有轮廓点到局部首尾连线的平均归一化距离。
- 计算眼、眉、嘴、下颌四个区域相对面部中轴的左右差异。
- 左右差异指数显示为百分比，不合成为“对称美貌分”。
- 头部偏转可信度不是“高”时，左右差异区显示“拍摄角度可能影响结果”。

### 6.7 五官量感

不再只输出一个不可解释的“淡颜/浓颜”。报告分别显示：

- 眼口横向量感：`(平均眼宽×2 + 嘴宽) / 脸宽`。
- 眉眼纵向紧凑度：`眉眼距离 / 平均眼宽`。
- 鼻部横向存在感：`鼻宽 / 脸宽`。
- 唇部纵向存在感：`(上唇厚度代理 + 下唇厚度代理) / 可见纵向长度`。

最终“轻量感 / 中等量感 / 强量感”是造型经验标签，必须允许展开查看四个组成数据。

## 7. 内置知识表

知识表作为 JavaScript 常量嵌入页面，不使用数据库。每项结构如下：

```js
{
  id: "eye_spacing",
  name: "眼间距关系",
  formulaText: "内眼角距离 ÷ 平均眼宽",
  evidenceType: "几何测量",
  referenceType: "古典五眼视觉参照",
  confidenceFactors: ["头部偏转", "眼睛闭合", "照片清晰度"],
  bands: [
    { max: 0.85, label: "相对集中", ruleId: "eye_concentrated" },
    { max: 1.15, label: "接近一眼宽参照", ruleId: "eye_reference" },
    { max: Infinity, label: "相对舒展", ruleId: "eye_spacious" }
  ],
  sourceIds: ["southern_chinese_canons"]
}
```

每条造型建议独立保存 `ruleId`、适用条件、建议、避雷、证据类型和解释。报告不得生成知识表中不存在的医学性断言。

## 8. 护肤基础路线

护肤路线只包含低风险基础建议：

- 早间：温和清洁或清水（按出油感受）、保湿、广谱 SPF 30+ 防晒。
- 晚间：温和清洁、保湿。
- 干性倾向：减少过度清洁，保湿涂在微湿皮肤。
- 油性倾向：选择不易堵塞毛孔的轻薄产品，不因出油跳过保湿。
- 敏感倾向：一次只新增一种产品，先做小范围试用；持续刺痛、红肿或皮疹时停止并咨询皮肤科医生。

不推荐具体品牌、浓度、酸类、维 A 类或美白活性成分。

## 9. 报告结构

### 9.1 第一屏：结论优先

- 照片与总可信度。
- 三个核心特征，每个用一句数据结论和一句行动建议。
- 第一目标对应的“现在先做什么”。

### 9.2 数据详情

默认折叠，按整体、眼眉、鼻唇、下颌分组。每张数据卡包含：

1. 通俗结论。
2. 原始数值与单位。
3. 计算方式。
4. 参考类型。
5. 当前可信度与影响因素。
6. “为什么给这个建议”。

### 9.3 造型建议

妆容、发型、穿搭各保留 2–3 条具体建议。每条建议标记“造型经验”，并说明关联数据。发型建议同时受面部数据、维护意愿和每日时间限制。

### 9.4 护肤路线

显示用户自评的肤质倾向和敏感倾向、早晚基础步骤、需要避免的过度叠加行为及皮肤科就医边界。

### 9.5 30 天行动卡

只生成三个任务：

- 第 1 周：建立清洁、保湿、防晒或现有基础复盘。
- 第 2 周：尝试一个与核心面部数据对应的妆容或发型变量。
- 第 3–4 周：在相同拍摄条件下记录体验，不做算法上的前后美貌比较。

任务按第一目标、时间和预算筛选。预算只影响建议复杂度，不推荐购买具体商品。

### 9.6 来源与导出

- 报告底部提供“依据与局限”抽屉，列出资料名称、链接、证据类型和产品启发式说明。
- 保存图片时包含核心结论、行动卡和免责声明，不包含完整公式，以控制图片长度。
- 完整网页报告保留展开公式和来源。

## 10. 错误与恢复

- 模型或脚本加载失败：显示失败资源类别、网络提示和重试按钮。
- 图片读取失败：恢复上传页并保留拍照指导。
- 质量门槛失败：显示唯一最主要的问题和重拍动作，避免一次列出多条错误。
- 计算出现非有限值或分母为零：隐藏对应指标并记录为“无法可靠测量”。
- 问卷未完成：允许查看几何报告，不生成护肤与完整行动卡。
- 复制失败：回退到临时文本框复制。
- 图片导出失败：提示使用浏览器打印或系统截图。

## 11. 隐私与可访问性

- 页面不发起任何用户数据上传请求；外部网络请求仅用于加载公开脚本和模型。
- 不使用 `localStorage`、Cookie、IndexedDB 或远程日志。
- 上传图片只转换为内存 Data URL，重新测试与刷新时清空引用。
- 所有交互可使用键盘，焦点状态可见。
- 状态变化使用 `aria-live`，错误信息使用 `role="alert"`。
- 尊重 `prefers-reduced-motion`。

## 12. 验收标准

### 12.1 公式测试

使用固定 68 点坐标样本验证：

- 三庭百分比总和约为 100%。
- 眼间距、眼角角度、鼻宽、嘴宽和下颌比例符合手工计算。
- 镜像对称坐标产生接近 0 的区域左右差异。
- 分母为 0 时不产生 `NaN` 或 `Infinity` 报告值。

### 12.2 流程测试

- 无脸、多脸、脸过小、歪头、明显偏转、模糊、过暗和过曝照片被正确拦截。
- 中等可信度照片显示警告并弱化左右差异解释。
- 六问可以前后导航，未完成状态不会生成护肤路线。
- 重新测试清除照片、关键点、问卷和报告。
- 模型重试后可以恢复上传。

### 12.3 内容测试

- 每条结论都有证据类型。
- 每条造型建议能追溯到至少一个测量或问卷答案。
- 护肤建议只来自允许的基础规则。
- 页面不存在美貌评分、健康诊断、性格推断或普适理想比例措辞。
- 来源链接可点击，产品启发式与研究来源明确区分。

### 12.4 设备测试

- 在常见手机宽度 320px、375px、390px 和桌面浏览器正常显示。
- 手机相册上传、拖放上传、复制关键词、展开数据和保存 PNG 可用。
- CDN 失败时页面仍显示可理解的错误和恢复动作。
