# 数据保留与删除

| 数据 | 常规保留与触发条件 | 删除方式 |
| --- | --- | --- |
| 人脸分析源照片、上传预留文件 | 正常在分析结束后立即安排清理；异常上传后最多 30 分钟触发清理 | 精确文件删除，失败保留重试任务；撤回同意或清空数据也触发 |
| 已保存身份卡与关联分析记录 | 保留至用户主动删除 | 单份删除或全部清空；撤回同意保留已完成报告 |
| 挑战、打卡 | 保留至用户主动删除 | 单组删除或全部清空 |
| 挑战照片 | 默认挑战完成七天后清理；现有 keep 策略可保留至主动删除 | 删除挑战或全部清空始终安排清理；上传链路仍未接通 |
| 分享预览及关联小程序码文件 | 分享创建后七天到期 | 到期先持久化文件清理意图，再移除预览；用户相关删除也触发 |
| 提醒订阅记录 | 单次消费；拒绝不可用于发送 | 删除挑战或全部清空会移除任务；已提交微信的发送无法撤回 |
| 同意、用户与挑战占用记录 | 按相应功能保留 | 全部清空移除；撤回人脸同意保留已撤回状态 |
| 删除意图与数量摘要 | 清理和核查所需期间保留 | 本版本尚无审计记录自动到期删除，不宣称完全抹除技术记录；发布前应确定并实施有限审计保留期限 |

“30 分钟”和“七天”是清理触发策略，不是故障期间物理删除成功的保证。任务执行依赖生命周期定时触发器、数据库权限和存储服务可用性。

## 状态如何解释

`accountApi` 返回 `reports`、`challenges`、`subscriptions` 数量，`photos` 包含 `queued`、`deleted`、`pending`，并返回 `auditId`、`acceptedAt` 和 `completedAt`。文件计数只包含该 `auditId` 关联的独立文件清理任务；同一账户同一文件去重，并可关联后续删除请求。只要该请求仍有待清理文件，`completedAt` 就是空值。状态刷新会重新计算，不能用“业务记录已移除”推断物理文件已经删除。

`deletion_jobs` 中的 `account-file` 任务先于业务记录删除落库，保存精确文件 ID，生命周期任务因此不依赖已经消失的父记录。空响应、错误文件 ID、非零状态及异常均不算成功；缺失文件 ID 保留为待人工核查。旧父记录型任务被接替时标为 `superseded`，保留原重试历史。审核记录不记录照片内容、报告或完整坐标。

挑战删除会先保存绑定当前用户与挑战编号的级联意图，再处理提醒、打卡、照片、占用记录和挑战本身；中断后可沿同一意图继续，不依赖已删除的挑战主记录。分享小程序码生成会在上传前登记进行中任务；清空账户会等待已登记任务结束，若预览已删除且上传文件回滚失败，该任务会转换为精确文件清理任务。提醒领取与发送都会在事务中复核挑战及删除意图，已成为孤立记录的提醒会失效而不发送。

生命周期扫描为精确账户文件和挑战级任务保留处理份额，其余删除意图使用游标轮转；已不存在父记录且缺少可验证文件目标的照片意图会标记为待人工核查，不会在没有存储回执时声称已删除，同时也不会长期遮挡后续清理。单次调度的扫描和尝试仍受 50 条上限约束。

## 发布前验证

公开 AppID 已配置，但尚无真实 EnvId；本地测试不等同部署验证。上线前必须配置并验证：当前用户数据库访问隔离、账户函数部署权限、生命周期定时触发器、存储精确删除回执、到期扫描索引、并发事务冲突重试、失败重试及人工核查流程。新增查询需要按 CloudBase 提示配置 `share_previews.expiresAt` 与各业务集合的 `_openid` / `_id` 等复合索引。

需使用真实环境验证超出单次函数执行时限的大账户删除与重试。删除分批处理，若中断会明确报告未完成，保留已落库文件任务，用户可重复请求。任务不会宣称已经部署，也不需要提供 AppSecret。

仍待完成：挑战照片上传链路、运营者联系方式、审计记录有限保留期及到期清除机制。持续并发的新建操作可能生成新的记录；清空数据不会永久禁用用户的后续使用。
